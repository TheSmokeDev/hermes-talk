Hermes Talk

Realtime duplex voice for your own agent. Talk to it, it runs real work in the background, it reports back out loud.

Hermes Talk is a realtime voice plugin for Hermes Agent. You speak, it answers out loud, and it calls the agent's own tools without leaving the conversation. It runs in the terminal, in a Discord voice channel, and in the Hermes dashboard.

It rides your ChatGPT or SuperGrok subscription. No API key required.

Install

hermes plugins install TheSmokeDev/hermes-talk --enable
python -m pip install "hermes-talk[audio]"
hermes talk

Needs Python 3.11 or newer and a Hermes Agent host v0.17 or newer. The [audio] extra adds microphone and speaker support; skip it if you only use the dashboard, where audio is browser-native.

What it is

Not dictation, and not read-my-reply-aloud. One bidirectional audio session where turn-taking, interruption and tool calls happen inside the speech layer:

  • Duplex. Cut it off mid-sentence and it stops, because it never stopped listening.
  • Its tools are the agent's tools. Realtime function calls relay straight into Hermes's real tool surface. Ask it something it cannot know and you hear it go look, then answer from what it found.
  • Work outlives the sentence. Delegation spawns a real background Hermes agent. You keep talking. The result is spoken when it lands.
  • It starts already knowing you. The session prompt is assembled from what Hermes itself knows, including your SOUL.md and whatever your configured memory provider contributes.

Providers

ProviderModelAuth
OpenAI Realtime (default)gpt-realtime-2.1a ChatGPT subscription through codex login, or an API key
xAI Grok Voicegrok-voice-latestan X Premium or SuperGrok login, no key; or an API key
Gemini Livegemini-3.1-flash-live-previewa Gemini API key; free-tier AI Studio keys work
GPT-Livegpt-live-1-codex / gpt-live-1the Codex subscription, or explicitly chosen API billing

So OpenAI Realtime and xAI Grok Voice ride a subscription today, and Gemini Live needs a key. GPT-Live is not a row in the provider knob — it is selected separately by TALK_VOICE_MODE=live, runs gpt-live-1-codex on the subscription and gpt-live-1 on API billing, and never falls back from one to the other.

A cascade lane can route speech through ElevenLabs for a custom voice. Provider support differs by surface, and the provider knob is fail-closed — it is never inferred from which keys happen to exist. hermes talk doctor names which lane came up and what is missing.

Is it working?

hermes talk doctor    # read-only diagnostics: auth lane, provider, model, voice, audio
hermes talk check     # doctor, plus one live provider turn and one bounded Hermes run
